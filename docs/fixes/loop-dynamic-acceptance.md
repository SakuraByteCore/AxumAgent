# `/loop` 动态循环验收与即时续跑

## 问题与根因

- 原实现只允许一次兜底。模型连续两轮未调用 `ScheduleWakeup` 时，任务被删除；复现应有第四轮却只有三轮（`3 !== 4`）。
- 首次修复保留循环，但仍设 20 分钟默认等待。按最终需求冻结时钟，从真实 Pi SDK 命令入口执行；显式延迟到期后只收到第二轮，缺少两次即时续跑（`2 !== 4`）。

## 修改

- `plugin/pi-companion/loop-scheduler.ts`：未指定延迟时，轮次结算即标记下轮到期。不再因漏调删除任务；保留显式延迟、停止、7 天到期和 `v1` 固定任务快照兼容性。
- `plugin/pi-companion/loop.ts`：创建动态循环后和轮次结算后安排一次事件循环回调，不等定时轮询。投递前检查会话空闲及用户消息队列，保留原定时器供显式延迟及固定任务调度。仍按原提示词执行，有失败、阻塞或缺证时不得标记通过；全部通过后才指示模型主动停止。
- `test/pi-loop-sdk.test.js`、`test/pi-loop.test.js`：冻结计时验证首轮、连续两次即时续跑、显式延迟不提前、停止及到期。
- `README.md`、`README.zh-CN.md`、`README.ja.md`：同步默认即时续跑；命令帮助及工具说明同步更新。

## 最终版验收

Windows、Node.js 22.20.0、Pi 0.99.2。由源码编译完整 `pi-companion`，从 Pi CLI 的 JSON RPC `prompt` 入口发出命令。使用 `127.0.0.1` 的确定性模型响应服务与受控时钟。

| 路径 | 实测结果 |
|---|---|
| `/loop 验收探针` | 四轮收到相同提示词和任务 ID。首轮指定 60 秒，59.999 秒未触发；到期后第二、三轮均不指定延迟。在时钟未再推进时收到第四轮 |
| 验收通过 | 第四轮停止成功；`/loop list` 为空，推进 1 小时无新投递 |
| 固定间隔、默认提示词及取消 | 固定任务按期投递普通文本 `/clear`；裸 `/loop` 使用项目 `loop.md`；按 ID 取消后无新投递 |
| 到期及退出 | 第 7 天最终轮完成后无后续投递；关闭 RPC 输入后进程退出码为 `0` |
| 既有回归与恢复 | `node --test test/pi-loop.test.js test/pi-loop-sdk.test.js test/pi-companion-vision.test.js` 共 33 项通过；真实 SDK 从磁盘恢复固定任务并执行；定向测试覆盖忙时与用户队列、动态任务不恢复、终端取消 |

修复后首轮定向测试通过。首次 CLI 脚本因正则语法错误未启动；仅修正本地测试脚本后复测通过，交付实现无返工或回滚。未验证外部模型的独立验收判断、交互式终端实体按键及已发布安装包；未测响应延迟数值。

## 回退

只还原本轮在两个 `/loop` 源文件、两个测试文件及三份 README 中的即时续跑差异；重新编译 `pi-companion` 后重启会话。回退到上一轮 20 分钟兜底逻辑，不恢复提前删除任务的旧缺陷，不迁移会话快照。
